# R.O.S.E. SOC Lab — local dashboard (Windows + WSL2)

This React/Vite UI connects to the existing FastAPI API through a **loopback-only development proxy**. It is a local web app, not a packaged Windows executable. The dashboard does not persist the bearer token in browser storage. Do not expose ports 8000 or 5173 publicly.

## Setup

In WSL2 terminal 1:

```bash
cd ~/ROSE-SOC-Lab/soc-lab
source .venv/bin/activate
# Create this once, if it does not exist. Never commit the token file.
[ -f .soc-token ] || (umask 077; python -c 'import secrets; print(secrets.token_urlsafe(48))' > .soc-token)
export ROSE_SOC_TOKEN="$(cat .soc-token)"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

In WSL2 terminal 2:

```bash
cd ~/ROSE-SOC-Lab/soc-lab/dashboard
npm install
npm run dev
```

Open http://127.0.0.1:5173 in your laptop browser. To unlock, use the value in your local `.soc-token` file. **Do not paste it into chat or GitHub.** If you previously saw `Invalid token`, restart the API using the token file above.

## WSL2 collector

In WSL2 terminal 3:

```bash
cd ~/ROSE-SOC-Lab/soc-lab
source .venv/bin/activate
export ROSE_SOC_TOKEN="$(cat .soc-token)"
python collector/wsl_metrics.py --once
# or continuously: python collector/wsl_metrics.py --interval 30
```

## Windows collector

The Windows PowerShell process needs the **same** token, but do not copy it into a command history or commit it. A convenient local-only transfer is to open the token file in Windows using Explorer at `\\\\wsl.localhost\\Ubuntu\\home\\<your-user>\\ROSE-SOC-Lab\\soc-lab\\.soc-token` (replace distro/user) and set `$env:ROSE_SOC_TOKEN` in your PowerShell session without saving it in scripts. Then run:

```powershell
cd "\\\\wsl.localhost\\Ubuntu\\home\\<your-user>\\ROSE-SOC-Lab\\soc-lab"
.\\collector\\windows_metrics.ps1 -Once
# or: .\\collector\\windows_metrics.ps1 -IntervalSeconds 30
```

Windows-to-WSL localhost forwarding varies with WSL networking settings; if the Windows collector cannot reach the API, check Windows `http://127.0.0.1:8000/health`. Do **not** solve this by exposing the API to the LAN.

## Privacy and scope

Collectors read only aggregate CPU and memory utilization and submit `system_metrics` events. They do not capture network traffic, process names, command lines, IP addresses, usernames, or credentials. SQLite and tokens remain local and gitignored. Alerts in the existing API are generated by existing event rules; metrics alone do not indicate threats. No automated remediation. This is a prototype, not a production endpoint detection product.
